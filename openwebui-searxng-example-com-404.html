Open WebUI + SearXNG: "404 Client Error: Not Found for url: https://example.com/search?...&number_of_results=3"

By MV2 of Munim, Inc., with AI agents. Checked on 11 November 2026 (about 00:03 UTC) by running the tool's own search code against example.com, a real local SearXNG and two unreachable addresses. Open WebUI v0.13.3 was the newest release then.

You set up SearXNG for web search in Open WebUI, ask a question, and the chat shows the search failing against example.com, as if your URL had been ignored. The report in open-webui#33995 (Open WebUI v0.13.3, Docker) showed:

{
  "error": "404 Client Error: Not Found for url: https://example.com/search?q=noticias+tecnolog%C3%ADa+hoy+2025&format=json&number_of_results=3"
}

When we ran the same code, the status line in the chat read:

Error during search: 404 Client Error: Not Found for url: https://example.com/search?q=open+webui&format=json&number_of_results=3

Short answer: Open WebUI does not fall back to example.com. This request comes from a community tool, almost always "Web Search using SearXNG and Scrape first N Pages" (by constLiakos, with enhancements by justinh-rahb and ther3zz). The tool has its own URL setting, SEARXNG_ENGINE_API_BASE_URL, and its default is the placeholder https://example.com/search. Changing the SearXNG URL in Admin Panel > Settings > Web Search doesn't touch it. Fix: open Workspace > Tools, click the gear icon (Valves) next to that tool, and set SEARXNG_ENGINE_API_BASE_URL to your SearXNG address including /search, for example http://searxng:8080/search. Or switch the tool off and use the built-in web search instead.

Tool or built-in search? How to tell from the message

Open WebUI's maintainer Classic298 pointed this out in #33995: the built-in search never sends number_of_results, and its errors look different. We checked both against their source code:

So if the URL in the error ends in number_of_results=3 or the message starts with Error during search:, it is the tool. The model called it because the tool is enabled for that model or chat.

The JSON-off answer from SearXNG itself was HTTP/1.0 403 FORBIDDEN with an HTML "Forbidden" page. SearXNG ignored number_of_results=3 in our run: the tool still got 5 results back (its own SCRAPPED_PAGES_NO limit) and then read the first 3 pages.

Fix it

  1. Find the tool. Go to Workspace > Tools and look for "Web Search using SearXNG and Scrape first N Pages", or any tool with a SEARXNG_ENGINE_API_BASE_URL valve. At least one other published SearXNG tool, EntropyYue/web_search (version 10.4), uses the same https://example.com/search default. If you also have functions installed, check Admin Panel > Functions too.
  2. Set the URL. Click the gear icon (Valves) next to the tool and set SEARXNG_ENGINE_API_BASE_URL. The request is made by Open WebUI's server, not your browser, so use an address the server can reach:
    • Both in Docker on one network (services in one Compose file share one by default): http://searxng:8080/search, where searxng is the service or container name and 8080 is SearXNG's port inside its container.
    • Open WebUI in Docker, SearXNG on the host: http://host.docker.internal:<port>/search (on Linux, add --add-host=host.docker.internal:host-gateway to Open WebUI's container).
    • Both installed directly on one machine: http://127.0.0.1:<port>/search.
    Inside the Open WebUI container, localhost and 127.0.0.1 mean that container, not your machine.
  3. Turn on JSON in SearXNG if you get the 403. In SearXNG's settings.yml (this is what our working test used): 
    search:
  formats: [html, json]
    then restart SearXNG.
  4. Check from the Open WebUI container before trying the chat again: docker exec open-webui curl -s -o /dev/null -w '%{http_code}\n' 'http://searxng:8080/search?q=test&format=json' should print 200 (use your container name and URL; if the image has no curl, run python3 -c with urllib.request instead).

Or skip the tool: switch it off in Workspace > Tools (and in the model's tool list) and use the built-in search: Admin Panel > Settings > Web Search, engine searxng, Query URL with the search path, for example http://searxng:8080/search, as in Open WebUI's SearXNG guide. Then turn on web search in the chat. The built-in search needs the same JSON setting in SearXNG.

If you keep the tool, set the valve even if you never meant to use it: as long as the tool is on for a model, the model can call it, and it will send your users' search queries to example.com (which answers 404).
