pip install open-webui: "Could not find a version that satisfies the requirement open-webui (from versions: none)"

By MV2 of Munim, Inc., with AI agents. Checked on 6 November 2026 by running pip 26.3 on Python 3.10, 3.11, 3.12, 3.13 and 3.14 against PyPI, where the newest Open WebUI is 0.13.0 (3 November 2026). For your own machines only.

The full error looks like this. The first line lists every release pip skipped, so it is shortened here:

ERROR: Ignored the following versions that require a different python version: 0.1.124 Requires-Python >=3.11,<3.12.0a1; 0.1.125 Requires-Python >=3.11,<3.12.0a1; …
ERROR: Could not find a version that satisfies the requirement open-webui (from versions: none)
ERROR: No matching distribution found for open-webui

Short answer: the Python that runs your pip is a version Open WebUI doesn't support. Every Open WebUI release tells PyPI which Python versions it works with, and pip quietly skips every release that doesn't fit. Open WebUI 0.13.0 requires <3.13.0a1,>=3.11, which means Python 3.11 or 3.12. On Python 3.13, 3.14, or 3.10 and older, pip skips all 154 releases, so it finds none. Your network, PyPI and your pip are fine, and upgrading pip doesn't help. Run Open WebUI on Python 3.12 instead: with uv, in a Python 3.12 virtual environment or in Docker.

Open WebUI's own Quick Start says the same: "Open WebUI supports Python 3.11 and 3.12", and Python 3.13 is not supported yet. No Open WebUI release on PyPI accepts Python 3.13 or newer. Releases before 0.5.0 (25 December 2024) accepted only Python 3.11.

1. See which Python your pip uses

python3 -m pip --version

It prints something like pip 26.3 from … (python 3.13). The number in brackets is the Python that pip installs for. On Windows, run py -m pip --version; py -0 lists the Pythons the launcher can find. Prefer python -m pip over a bare pip: then you know which Python you're installing into.

2. Fix: run it with uv (what Open WebUI's docs suggest)

uv fetches Python 3.12 for Open WebUI and leaves your own Python alone. These are the commands from Open WebUI's Quick Start. macOS and Linux:

DATA_DIR=~/.open-webui uvx --python 3.12 open-webui@latest serve

Windows (PowerShell):

$env:DATA_DIR="C:\open-webui\data"; uvx --python 3.12 open-webui@latest serve

Keep DATA_DIR: the docs warn that without it, uvx might store your data in a temporary folder that gets deleted when the process ends.

3. Fix: a virtual environment on Python 3.12

If Python 3.12 is installed (from python.org, your package manager, or uv python install 3.12), give Open WebUI its own environment. macOS and Linux:

python3.12 -m venv ~/open-webui-venv
~/open-webui-venv/bin/python -m pip install open-webui
~/open-webui-venv/bin/open-webui serve

Windows (PowerShell):

py -3.12 -m venv "$env:USERPROFILE\open-webui-venv"
& "$env:USERPROFILE\open-webui-venv\Scripts\python.exe" -m pip install open-webui
& "$env:USERPROFILE\open-webui-venv\Scripts\open-webui.exe" serve

Update later with the same environment's pip: -m pip install -U open-webui.

4. Or use Docker

Open WebUI's docs say its Docker image runs Python 3.12 on Debian 13, so the Python on your computer doesn't matter. Follow the Docker steps in the Quick Start.

Don't force it with --ignore-requires-python. That makes pip try to install Open WebUI on a Python it doesn't support. Open WebUI's docs say Python 3.13 is not supported yet because a handful of its dependencies still need to ship 3.13-compatible releases. Use Python 3.12, then check your version against Open WebUI's security advisories.

The other wording: "requires a different Python"

ERROR: Package 'open-webui' requires a different Python: 3.13.18 not in '<3.13.0a1,>=3.11'

Same cause, found at a different moment. pip prints this when it only learns a package's Python requirement from the file itself, for example when you install a downloaded wheel, or when a package mirror doesn't list each release's Python requirement. The fix is the same: use Python 3.11 or 3.12.

Why the message looks like this

pip 26.3 skips each release whose Requires-Python range doesn't include your Python, and lists them after "Ignored the following versions that require a different python version". If nothing is left, _report_single_requirement_conflict in factory.py prints "(from versions: none)" and "No matching distribution found for open-webui". The "requires a different Python" wording comes from _report_requires_python_error in the same file. Each release's range is on PyPI: for 0.13.0 it is <3.13.0a1,>=3.11.
