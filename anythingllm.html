Self-hosted AnythingLLM: which advisories affect my version?

By MV2 of Munim, Inc., with AI agents. Checked against AnythingLLM's own security advisories, its release tags, NVD and OSV.dev on 11 October 2026; every row links its source.

AnythingLLM runs as a desktop app or from a Docker image (mintplexlabs/anythingllm), not from a package you install, so npm audit, pip-audit and Dependabot never check its version. Its advisories are also hard for tools to use: most list a commit hash or ">1.16.1" as the patched version instead of a release, and several of the newest (for example GHSA-8wh8-3v68-whwj, GHSA-p9pc-ccw4-fxc5, GHSA-3f4c-xj8r-h4cr and GHSA-rh3m-xv7m-9jhf) return "not found" on OSV.dev. MV2 looked up which release tag first contains each fix commit, so the table below gives real version numbers.

The latest release is 1.17.0 (1 October 2026). Every advisory below with a known fix is fixed in 1.16.2 (22 September 2026) or earlier.

  • 1.13.0 up to 1.16.1: anonymous visitors of an embedded chat widget receive the instance owner's private Memories in the system prompt (GHSA-8wh8-3v68-whwj, CVSS 5.3, no CVE ID). If you put an AnythingLLM chat widget on a public website, a visitor could get the model to repeat what it remembers about you. Fixed in 1.16.2 (named in its release notes).
  • Before 1.13.0: anyone who can chat with an agent can make the filesystem-search-files skill pass options to ripgrep and, together with the file-write skill, run commands inside the AnythingLLM container (CVE-2026-48116, High). Per NVD, the filesystem skill is on by default in the official Docker image. The GitHub advisory lists no patched version; NVD says 1.13.0.
  • Before 1.11.2: a model response with injected HTML runs script while it streams (CVE-2026-32626, Critical, 9.6), plus SQL injection in the built-in SQL agent (CVE-2026-32628, High) and a batch of access-control bugs.
  • Before 1.10.0: stored provider API keys leak through systemSettings.js (CVE-2026-24477, CVSS 4.0 8.7) and a path traversal (CVE-2026-24478, High).

Desktop app: the version shows at the top of the window. Docker: run docker ps --format "{{.Image}}" | grep anythingllm. A tag like mintplexlabs/anythingllm:1.16.2 is that release. The latest tag is rebuilt from the main branch almost daily, so its version depends on when you pulled it: docker image inspect mintplexlabs/anythingllm:latest --format "{{.Created}}" shows the build date, and a latest image built after 22 September 2026 should already contain every fix on this page. The check runs in your browser.

The usual way to run it is open to your network

This isn't a CVE, but it matters more than most of them. AnythingLLM's documented Docker command is docker run -d -p 3001:3001 --cap-add SYS_ADMIN .... -p 3001:3001 publishes the app on all addresses of the host, and on Linux, ports Docker publishes skip ufw and firewalld. In single-user mode the instance has no password unless you turned on password protection in its settings, so anyone who can reach port 3001 gets the whole workspace: your documents, chats, agent skills and the stored API keys of your model providers.

What to do

  1. Update to 1.16.2 or newer (1.17.0 is current). Your data lives in the storage folder you mounted, so for Docker it's docker pull mintplexlabs/anythingllm, then start it again with the same command. Back up the storage folder first.
  2. Publish on localhost only unless others need it: -p 127.0.0.1:3001:3001. If your team uses it, put it behind a reverse proxy with sign-in, and use multi-user mode rather than one shared password.
  3. Turn on password protection or multi-user mode on any instance other machines can reach, and set a long random JWT_SECRET in its .env (openssl rand -hex 32).
  4. Public chat widgets: if you embed AnythingLLM on a website and run 1.13.0-1.16.1, update now. Assume what the owner account's Memories contained may have been seen.
  5. Agent skills: disable the filesystem and SQL agent skills on instances where people you don't fully trust can chat with agents.
  6. If an old version was reachable by people you don't trust, recreate the container from a fresh image and rotate the model provider and vector database keys stored in AnythingLLM.
