Self-hosted RAGFlow: which advisories affect my version?

By MV2 of Munim, Inc., with AI agents. Checked against RAGFlow's own security advisories, OSV.dev and RAGFlow's source code; first written 11 October 2026, fix status of GHSA-c6q8 updated 12 October 2026. Every row links its source.

RAGFlow runs from a Docker image (infiniflow/ragflow), not from a package you install, so pip-audit, npm audit and Dependabot never check RAGFlow's own version. Image scanners such as Trivy look at the libraries inside the image, not at RAGFlow's advisories. And RAGFlow's advisories are unusually hard to read correctly: seven of its eight GitHub advisories list no patched version, even where a later release did fix the bug. This page sorts out which are really fixed and which are not.

The latest 0.x release is 0.27.2. 1.0.0-rc1 (29 September 2026) is a release candidate: a large rewrite whose default API server is new Go code, with a one-way data migration (RAGFlow's notes say data can't be rolled back to 0.27.2).

  • 0.25.2 up to 0.27.2, no fixed 0.x release: any signed-in user or API key holder who knows an agent's ID can run another user's private ("Only me") agent through the OpenAI-compatible endpoint POST /api/v1/agents/chat/completions and read its output (GHSA-c6q8-23rp-32cv, CVSS 7.1, published 5 October 2026). It has no CVE ID, and OSV.dev returns "not found" for its GHSA ID. The advisory still lists no patched version.
    Update, 12 October: the Python fix is PR #19817 ("Fix authorization for OpenAI-compatible agent completions", merged 18 September 2026), which moves the agent access check ahead of the OpenAI-compatible branch in api/apps/restful_apis/agent_api.py. MV2 checked the git history: that commit is in v1.0.0-rc1 and not in v0.27.2. But 1.0.0-rc1's docker/.env sets API_PROXY_SCHEME=go, so by default the request is served by the new Go handler, not the patched Python code, and the advisory doesn't say whether that path is covered. Until RAGFlow updates the advisory, treat 1.0.0-rc1 as "probably fixed, not confirmed".
  • Before 0.25.0: any signed-in user can run operating-system commands on the server through Jinja2 templates in the agent Text Processing and Message components (CVE-2026-28797) and in the prompt generator (CVE-2026-45312, CVSS 9.9). Sign-up is open by default (REGISTER_ENABLED=1), so "signed-in user" can mean anyone who reaches the login page. Both advisories, and their OSV records, still list no patched version. MV2 checked the source: in 0.25.0 both agent/component/string_transform.py and rag/prompts/generator.py render templates with Jinja2's SandboxedEnvironment, and the 0.25.0 release notes say "Fix jinja2 SSTI vulnerability using SandboxedEnvironment". So 0.25.0 or newer closes them.
  • Before 0.24.0: Zip Slip in the MinerU parser lets a malicious ZIP overwrite files on the server (CVE-2026-24770, CVSS 9.8). The advisory lists no patched version; MV2 checked that its fix commit (64c75d5) is in 0.24.0. It matters only if you use MinerU parsing.
  • Before 0.23.0: any signed-in user can run commands on the host through the Canvas CodeExec component (CVE-2025-68700).
  • Before 0.22.0: anyone with a shared assistant or agent link could derive the owner's personal API key and take over the account (CVE-2025-69286, CVSS 4.0 9.3).

Find it with docker ps --format "{{.Image}}" | grep ragflow (for example infiniflow/ragflow:v0.27.2), or read RAGFLOW_IMAGE in ragflow/docker/.env. If the tag is nightly or latest, the version depends on when you pulled it (on 12 October 2026, Docker Hub's latest was the same image as nightly, built from the main branch after 1.0.0-rc1, not 0.27.2). The check runs in your browser.

The default Docker setup exposes more than RAGFlow

This isn't a CVE, but on many installs it's the bigger risk. In RAGFlow 0.27.2's docker/docker-compose-base.yml, the default services publish their ports on all addresses of the host:

ServiceHost port (default)Default password in docker/.env
Elasticsearch (the default document engine)1200ELASTIC_PASSWORD=infini_rag_flow
MySQL3306MYSQL_PASSWORD=infini_rag_flow
MinIO (your uploaded files)9000, console 9001MINIO_PASSWORD=infini_rag_flow
Redis6379REDIS_PASSWORD=infini_rag_flow
RAGFlow web, API, admin and MCP80, 443, 9380, 9381, 9382app accounts; sign-up open by default

The file itself says "SECURITY WARNING: DO NOT DEPLOY WITH DEFAULT PASSWORDS". Only the sandbox executor is bound to 127.0.0.1. On Linux, ports Docker publishes skip ufw and firewalld, so a host firewall doesn't protect them.

1.0.0-rc1 adds services to the default profile list (COMPOSE_PROFILES now includes ragflow-go and clickhouse): NATS (4222, plus monitoring on 8222), Kvrocks (6379) and ClickHouse (9900 and 8123), also published without a host address. Before the first start of a 1.0 install, go through docker/.env and replace every default password, including ADMIN_DEFAULT_PASSWORD and CLICKHOUSE_PASSWORD, and bind every port that only RAGFlow's own containers use to 127.0.0.1 or remove its ports: line.

What to do

  1. Be on 0.27.2 at least. Back up docker/volumes and your .env first, then follow RAGFlow's upgrade guide. Moving to 1.0.0-rc1 brings the Python fix for GHSA-c6q8, but it's a release candidate with a one-way migration: test it on a copy first.
  2. Turn off open sign-up if only your team uses it: set REGISTER_ENABLED=0 in docker/.env and recreate the containers. On anything before 0.25.0, open sign-up means anyone who reaches the page can run commands on your server.
  3. While you're on 0.27.2 or older, treat every agent as readable and runnable by every account and API key on the instance. Don't put secrets or tools with side effects in agents on a shared instance, and don't share agent IDs.
  4. Change the default passwords (openssl rand -hex 32 gives a strong one), and publish the database and queue ports on 127.0.0.1 only, for example "127.0.0.1:${ES_PORT}:9200", or remove their ports: lines if nothing outside Docker needs them.
  5. If an affected version was reachable by people you don't trust, rebuild from fresh images and rotate the model provider API keys stored in RAGFlow.
