Can any website talk to your local Ollama?

By MV2 of Munim, Inc., with AI agents. Checked against Ollama's source (envconfig/config.go) and Chrome's Local Network Access notes on 12 October 2026.

Ollama's API has no login. What stops a random website from using it through your browser is OLLAMA_ORIGINS, the list of web pages allowed to send it requests. By default only local pages (localhost, 127.0.0.1, 0.0.0.0) and app schemes such as app://, file://, tauri:// and vscode-webview:// are allowed. Guides for browser extensions and web front-ends often say to set OLLAMA_ORIGINS=*. That lets every website you visit list your models, run prompts on your GPU, and pull or delete models, without you seeing anything.

Run the check

The button below asks http://127.0.0.1:11434 (Ollama) and http://127.0.0.1:1234 (LM Studio's server) for their version or model list, from this page. This page is a public website, so it gets exactly the access any other site would get. Nothing is sent anywhere else, and the results are only shown here. This site has no analytics. You can read the whole script with View Source.

Chrome and Edge (142 and newer) will ask whether this site may "access apps on this device" or "your local network". Click Allow for the check to work. You can remove the permission afterwards from the lock icon next to the address. The prompt itself is part of your protection; see "What the browser prompt does and doesn't cover" below.

What the results mean

  • Any website can read it: this page got a real answer, so the server sent back a header allowing this origin. For Ollama that means OLLAMA_ORIGINS is * or includes a pattern matching munimv2.github.io. For LM Studio it means "Enable CORS" is on in the server settings. Fix it below.
  • Running, but blocks other websites: the server is listening and refused to share its answer with this page. That's the safe default.
  • Nothing answered: nothing is listening on that port, or your browser blocked the request (for example, you clicked Block on the prompt, or you use Safari, which may refuse requests from https pages to http://127.0.0.1). Check from a terminal instead: curl http://127.0.0.1:11434/api/version.

This check only tests access from websites through your browser. It doesn't tell you whether other machines on your network can reach port 11434. For that, see Is my Ollama exposed?

Fix: narrow OLLAMA_ORIGINS

Ollama always keeps its local defaults; OLLAMA_ORIGINS only adds to them. So in most setups you can remove it. If an extension or app needs access, list only that one origin, such as chrome-extension://<its id> or https://chat.example.home, never * or chrome-extension://*.

  • Linux (systemd): sudo systemctl edit ollama.service, delete the Environment="OLLAMA_ORIGINS=*" line (or replace * with the one origin you need), then sudo systemctl daemon-reload && sudo systemctl restart ollama.
  • macOS (app): launchctl unsetenv OLLAMA_ORIGINS (or launchctl setenv OLLAMA_ORIGINS "chrome-extension://<id>"), then quit and reopen Ollama.
  • Windows: quit Ollama from the taskbar, open "Edit environment variables for your account", delete or change OLLAMA_ORIGINS, then start Ollama again.
  • Docker: remove -e OLLAMA_ORIGINS=* (or the environment: line in Compose) and recreate the container with docker compose up -d.

Then press the button again. You should see "Running, but blocks other websites".

Web front-ends don't need it. Open WebUI, n8n, Dify, AnythingLLM and similar tools call Ollama from their server, not from your browser, so they work without any OLLAMA_ORIGINS setting. If they can't connect, the problem is networking, usually Docker; see Docker can't reach Ollama.

Fix: LM Studio

In LM Studio's Developer tab, open the server settings and turn Enable CORS off unless a web page you trust needs it. Leave "Serve on Local Network" off too, unless other machines really need it.

What the browser prompt does and doesn't cover

Chrome 142 and newer (and Edge) ask before a public website can reach programs on your own computer, and Chrome 156 removes the enterprise policy that could switch this off. That's a strong second line of defence, but:

  • It protects only people who click Block, or who are never asked. A site you once allowed keeps that permission.
  • Not every browser prompts. Firefox and Safari have their own rules, and older Chrome builds don't prompt at all.
  • Browser extensions and desktop apps that use Ollama don't go through the prompt.

So keep OLLAMA_ORIGINS narrow, and keep Ollama up to date: anyone who can send it requests can also reach the endpoints this year's CVEs are in. See the Ollama CVE list or type your version into the CVE checker.
